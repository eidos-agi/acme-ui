acme ui / reference chat

One demo, grown in public.

The same scripted agent turn, rebuilt version by version until it passes the full calm-legibility checklist. Every version stays online — the point is the distance between them.

  1. v0 live

    The naive baseline. Text streams, tools run — but raw output dumps inline, the view yanks while you read, and there is no Stop. Watch it and feel what "overwhelmed" means.

  2. v1 next

    Control: Send morphs to Stop, abort keeps the partial, late events after abort are dropped instead of flickering in.

  3. v2 planned

    Disclosure: tool activity becomes collapsed rows with live state and elapsed time — depth one click away, never forced.

  4. v3 planned

    Calm: scroll pin with jump-to-latest, recoverable error that keeps partial output, full checklist pass.

Built from brief 01 in eidos-agi/ui-patterns: a scripted event stream (chat-events v1.1) and an acceptance checklist. Versions advance only by fixing a named failure from the checklist — growth you can diff.

Every version talks to the same mock agent — a scripted "server" speaking the event contract, abort semantics and late-token traps included. The agent never changes between versions; only the frontend grows up. New mock versions appear when a demo needs new server behavior (replay, approvals).
